# KBRAG — как запустить

Локальная база знаний по вашим статьям. Разбирает PDF с диска — текст, таблицы,
формулы, рисунки, номера страниц, — складывает в базу и отвечает: поиском,
чат-ботом на Qwen3 со ссылками на статьи и графом знаний — в браузере и в
Телеграме. Баз может быть несколько, на разные темы, деревом. Всё работает на одной
машине, в интернет не ходит.

Все команды одинаковые для любого терминала и начинаются с `python kbrag.py`.
Полный список — `python kbrag.py help`.

---

## 1. Что поставить один раз

| Что | Зачем | Где взять |
|---|---|---|
| **Python 3.12** | на нём написан проект | python.org → Downloads. При установке отметить **«Add python.exe to PATH»** |
| **Docker Desktop** | в нём живут база (PostgreSQL + pgvector) и языковая модель Qwen3 (vLLM) | docker.com → Docker Desktop |
| Видеокарта NVIDIA, от 16 ГБ | на ней работает языковая модель; ещё ускоряет разбор PDF и векторы в разы | без неё работают импорт статей и поиск, но не чат-бот и не граф |

Модель ставить отдельно не нужно: `python kbrag.py start` сам скачает при первом
запуске образ vLLM (около 9 ГБ) и модель Qwen3-14B (около 10 ГБ) и поднимет их
вместе с базой. Модель грузится 1–2 минуты.

Без модели работает всё, кроме чат-бота и графа: импорт, поиск и статьи — да.

---

## 2. Как открыть терминал в папке проекта

1. Откройте папку проекта в Проводнике.
2. Щёлкните по адресной строке сверху, сотрите путь, наберите `cmd` и нажмите Enter.

Откроется чёрное окно — командная строка, уже в папке проекта. Все команды
ниже набираются в нём. Подойдёт и любой другой терминал, если перейти в папку
проекта.

---

## 3. Первый запуск на новой машине

По порядку, один раз:

```
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

Первая команда создаёт окружение проекта, вторая ставит в него библиотеки —
это несколько минут и пара гигабайт.

Если есть видеокарта NVIDIA, поставить сборку с её поддержкой (для RTX 50-й
серии — cu128) и проверить:

```
.venv\Scripts\python -m pip install --force-reinstall torch torchvision --index-url https://download.pytorch.org/whl/cu128
.venv\Scripts\python -c "import torch; print(torch.cuda.is_available())"
```

Должно напечатать `True`.

Дальше — запустить Docker Desktop (значок кита должен перестать мигать) и:

```
python kbrag.py start
python kbrag.py init
```

`start` поднимает базу, `init` создаёт в ней таблицы.

Окружение `.venv` запускатель находит сам: набирать можно обычный `python`,
библиотеки всё равно возьмутся из `.venv`.

## 4. Инструменты

### Свои статьи в базу

```
python kbrag.py import "D:\Статьи\Оптика" --kb physics.optics
```

Берёт PDF — один файл или папку целиком, с подпапками, — разбирает каждый (разделы,
таблицы, формулы, номера страниц), сохраняет рисунки файлами и загружает статьи в
базу, в ветку дерева `--kb` (ниже, «Дерево баз»). Сам PDF никуда не копируется:
запоминается путь к нему и отпечаток файла. Тот же файл второй раз не разбирается —
повторный `import` той же папки пропускает уже разобранное и разбирает только новое.

Название, авторов, год и журнал программа берёт:

1. из файла `.yaml` рядом с PDF — с тем же именем (`статья.pdf` → `статья.yaml`):
   ```
   название: Строение Северного блока
   авторы: Иванов И. И.; Петров П. П.
   год: 2021
   журнал: Оптика и спектроскопия
   doi: 10.1234/abcd
   ```
2. из файла `.bib` в той же папке — например, экспорт из Zotero или JabRef: запись
   находится по имени PDF;
3. из самого PDF — его свойств и DOI на первых страницах.

Чего нет нигде, можно спросить: `--ask` — программа спросит в окне название,
авторов, год, журнал и DOI (Enter — пропустить). Без названия статья называется по
имени файла.

Полезные ключи: `--figures` — ещё и описать рисунки моделью со зрением (её описание
становится фрагментом, его находит поиск; модель поднимается сама, на 16 ГБ — на
время описания вместо модели ответов: `docs\КОМАНДЫ.md`, «Рисунки»); `--force` —
разобрать заново и уже разобранный файл. Описать рисунки уже загруженных статей —
`python kbrag.py figures`.

Рисунки фрагментов, на которые сослался ответ, видны под ответом на странице и
приходят фото в Телеграме.

Сканы (страницы-картинки без текстового слоя) не разбираются — в отчёте у них
«скан». С `--ocr` текст сканов распознаётся (медленно, нужен движок распознавания —
`docs\КОМАНДЫ.md`, «Сканы»).

После загрузки модель пишет резюме статей и разделов — по ним чат-бот ищет «сверху
вниз» и отвечает на обзорные вопросы. Модель не запущена — потом:
`python kbrag.py summaries`.

Формулы распознаются в LaTeX и показываются формулами — на странице и в ответах
чат-бота (с номером «(N)» из статьи), в Телеграме — картинкой по кнопке под
фрагментом. Найти формулу: `python kbrag.py formula <doc_id> 55` или по смыслу —
`python kbrag.py formula --find "плотность через пористость"`.

### Разобрать заново

```
python kbrag.py reparse --kb physics.optics
python kbrag.py reparse 10.1234_abcd
```

Разбирает статьи базы заново из их PDF — после обновления программы или если
поменялись настройки разбора. Граф не теряется: у фрагментов, чей текст не
изменился, факты остаются, даже если фрагменты сдвинулись (новый абзац, другая
нарезка), — модель пройдёт только изменившиеся. Статьи, у которых
PDF нет (так загружалась прежняя добыча из интернета), переразобрать нельзя, пока
не импортировать их файл: `import` узнает тот же файл по отпечатку и запомнит путь.

### Загрузить в базу

```
python kbrag.py ingest
```

`import` загружает статьи сам; `ingest` нужен, только если статьи разобраны, но не
загружены (`import --no-ingest`) или базу пересоздали. Разобранное режется на
фрагменты, каждый переводится в вектор и ложится в базу; у каждого фрагмента
определяется язык. Уже загруженное пропускается. Новые статьи ложатся в выбранную
базу дерева (`--kb`).

### Дерево баз

Баз знаний может быть несколько, на разные темы, и они складываются в дерево:
`physics` → `physics.optics` → `physics.optics.lasers`. Имя узла — латиница, цифры и
`_`. Любой команде можно сказать, с какой базой работать:

```
python kbrag.py web --kb physics.optics
python kbrag.py ask "какие методы описаны в статьях?" --kb physics
python kbrag.py graph --kb physics.optics
python kbrag.py eval --kb .
```

База — это и статьи её поддерева: `--kb physics` ищет по всем базам о физике сразу,
`--kb .` — по всему дереву. Без ключа — база из строки `база_по_умолчанию` в
`config\kbs\kb.yaml`; там пусто — всё дерево. Одна и та же статья может лежать в
нескольких ветках.

В дереве уже есть ветка `geology` (`geology.ore.anabar`) — настройки базы, с которой
начинался проект: слова темы, синонимы и правила графа для рудной геологии. Её
можно взять за образец своей базы или убрать вместе с папкой настроек: `python kbrag.py kb remove geology --config`.
Статьи, загруженные до дерева баз, кладёт в ветку `python kbrag.py init --kb <ветка>`.

У каждой базы — своя папка настроек в `config\kbs`, по папке на шаг пути
(`config\kbs\physics\optics`): `kb.yaml` — название и слова темы, которыми бот
говорит с моделью («вопрос физика», «статьи по оптике»),
`synonyms.yaml`, `graph-rules.txt`, `eval-questions.yaml`. Чего у базы нет,
берётся выше по дереву: у новой базы о физике без своих настроек будут общие слова
из `config\kbs\kb.yaml`. Чтобы бот заговорил о её теме, достаточно папки с
`kb.yaml`, где написано своё — что значит каждое слово, сказано в корневом
`kb.yaml`.

Что команды делают для базы на этой машине (предложения синонимов, таблицы фактов,
вопросы из графа), ложится в `.local\kbs\<путь базы>`.

Само дерево — командами `kb`:

```
python kbrag.py kb list
python kbrag.py kb create physics.hadron.elsm --title "Модель ЭЛСМ"
python kbrag.py kb move physics.optics physics.waves.optics
python kbrag.py kb assign physics.hadron 10.1103_physrevc.99.000001
python kbrag.py kb unassign physics.hadron 10.1103_physrevc.99.000001
python kbrag.py kb remove physics.old
```

- `list` — все базы деревом: название, сколько статей в самой базе и вместе с базами
  под ней, какая по умолчанию.
- `create` — новая база: папка настроек с `kb.yaml` (в нём подсказки, что можно
  написать) и запись в базе. Статьи в неё — `import … --kb physics.hadron.elsm`.
- `move` — перенести базу со всем, что под ней: статьи, папки настроек и данных, а если
  это база по умолчанию — и строку в `config\kbs\kb.yaml`. Настройки после переноса
  наследуются от новой ветки.
- `assign` / `unassign` — положить статьи в базу или убрать из неё (сами статьи
  остаются в базе знаний и в других своих ветках). Вместо списка статей — `--from
  другая.база` (все её статьи) или `--unplaced` (статьи без ветки).
- `remove` — сначала только показывает, что уберётся; убирает — с `--yes`. Статьи из
  других веток остаются там, лежавшие только здесь — без ветки (с `--docs` — удаляются
  из базы знаний). Папка настроек остаётся, удалить и её — `--config`.

На странице в браузере база выбирается вверху, в Телеграме — командой `/kb`.

### Кому какие базы

По умолчанию все, кого программа пускает, видят все базы: страницу — тот, кто открыл
её на этом компьютере, бота — люди из `.local\telegram_users.txt`. Чтобы у людей был
доступ только к своим базам, раздайте его командой `access`:

```
python kbrag.py access add Анна --kb physics.optics --kb chemistry --telegram 123456789
python kbrag.py access add Борис --kb .
python kbrag.py access list
python kbrag.py access remove Анна --kb chemistry
python kbrag.py access token Анна
python kbrag.py access remove Анна
```

- `add` — человек и его ветки. Ветка даёт доступ ко всему, что под ней, `.` — ко
  всему дереву. `--telegram` — его id в Телеграме: бот пришлёт его в ответ на любое
  сообщение. Повторный `add` дописывает ветки.
- При первом `add` программа печатает **токен** и ссылку для входа на страницу
  (`http://localhost:8000/?token=…`). Токен показывается один раз, в файле хранится
  только его отпечаток. Потерян — `access token ИМЯ` выдаст новый, старый перестанет
  работать.
- `remove` с `--kb` убирает ветку, без него — человека целиком.
- `access guests --kb …` — что видит гость открытого бота («*» в
  `telegram_users.txt`); без ключа — ничего.

Всё записывается в `.local\access.yaml` (только на этой машине, в git не идёт; можно
править и Блокнотом). Как только этот файл появился:

- **страница** пускает только по токену и показывает человеку только его ветки: в
  выборе базы, в поиске, чат-боте, графе, статьях, формулах и рисунках. Чужая статья
  по прямой ссылке отвечает «нет такой статьи»;
- **Телеграм-бот** отвечает и людям из `access.yaml` (по `--telegram`) — каждому по
  его веткам. Владельцы из `telegram_users.txt` по-прежнему видят всё;
- **Claude Code** (MCP) ходит со своим токеном: `KBRAG_TOKEN` в `.local\settings.env`
  или в окружении.

Команды в терминале (`search`, `ask`, `graph`…) видят всё: у кого терминал, у того и
база. Статья, не разложенная ни по одной ветке, видна только тому, у кого доступ ко
всему.

В групповом чате бот отвечает по правам того, кто пишет, а кнопки под ответом видят все
в группе. Чтобы у людей с разным доступом ответы не смешивались, давайте им бота в
личных сообщениях.

### Поиск, статьи и чат-бот — в браузере

```
python kbrag.py web
```

Откроется `http://localhost:8000`. Вверху — с какой базой работать: дерево баз
списком, «Все базы» — всё дерево; выбор помнит браузер, а ссылкой с `?kb=` можно
поделиться выбранной базой. Примеры вопросов под чатом — свои у каждой базы
(`примеры_вопросов` в её `kb.yaml`). Вкладки:

- **Поиск** — фрагменты статей по запросу. Ищет двумя способами сразу — по
  смыслу и по точным словам; русский запрос находит и английские статьи.
- **Статьи** — что разобрано, с разбором каждой статьи по фрагментам.
- **Чат-бот** — вопрос своими словами, ответ Qwen3 только тем, что бот нашёл
  в базе, и ищет вместе с моделью: Qwen3 делит сложный вопрос на части,
  составляет запросы (по-русски и по-английски), читает найденное, берёт только
  подходящее и, если чего-то не хватает, ищет ещё. Потом пишет ответ только по
  отобранному; после каждого утверждения — номер фрагмента, щелчок по нему
  открывает фрагмент и статью. Под ответом — **статьи, на которые он опирается**:
  авторы, год, название, журнал, номера их фрагментов и ссылки — DOI, страница
  издателя и свой PDF, открытый сразу на процитированной странице. В Телеграме —
  тот же список, а свой PDF статьи присылает кнопка «PDF n». Нужно подробно или кратко — так и напишите в
  вопросе, настроек нет. На вопрос «что
  известно о …» (объекте, методе, процессе) ответ собирается
  из датасета — все факты из всех статей базы, а не несколько найденных кусков.
  Если в базе такой информации нет — статьи не показываются: бот пишет
  «По вашему запросу в базе знаний такой информации нет» и ниже отвечает из
  общих знаний модели, с пометкой, что это не из базы. Можно спрашивать
  вдогонку («а при нагреве?») — он помнит разговор.
  Вкладка «Граф связей» — **граф знаний**, как в Obsidian, с поиском узла: сущности из статей и сами
  статьи; стрелка — факт («зона — входит в — щит»). Щелчок по сущности — внизу
  все факты о ней с цитатами и статьями; щелчок по статье — о чём в ней факты.

Под полем вопроса — две галочки. «Сверять, не расходятся ли статьи» — около 4 с
до начала ответа. «Быстрый режим» — вопрос не разбирается моделью, статьи не
сверяются: поиск, реранкер и сразу ответ; на простой вопрос — то же за меньшее время,
на сложный, из нескольких частей, — хуже. В Телеграме то же — `/fast` и `/conflicts`.

Найденное для ответа отбирает реранкер — отдельная небольшая модель
(bge-reranker-v2-m3, около 2 ГБ, скачивается сама при первом вопросе), а Qwen3 —
только если подходящего мало: тогда она говорит, чего не хватает, и бот ищет ещё.
Сколько занял каждый шаг, видно в «Как искал».

Окно терминала при этом не закрывать: пока оно открыто, страница работает.
Остановить — Ctrl+C в нём.

Чат-боту нужна работающая модель (`python kbrag.py start`; `web` поднимает её и
сам). Её состояние видно вверху вкладки: зелёная точка — готов, рыжая — что не
так и что сделать.

То же без браузера:

```
python kbrag.py search "методы измерения вязкости расплавов"
python kbrag.py ask "какие методы измерения вязкости описаны в статьях?"
```

### То же в Телеграме

Страница в браузере остаётся, бот — дополнительно. Он работает на вашем
компьютере: пока компьютер включён и бот запущен, ему можно писать с телефона
откуда угодно.

Один раз:

1. В Телеграме найти **@BotFather**, отправить ему `/newbot`, придумать имя и
   адрес бота (адрес кончается на `bot`). BotFather пришлёт токен — длинную
   строку вида `123456789:AA…`.
2. Сохранить токен в папке проекта:
   ```
   python -c "open('.local/telegram_token.txt','w',encoding='utf-8').write('ТОКЕН')"
   ```
3. Запустить бота и написать ему в Телеграме что угодно — он ответит «Нет
   доступа. Ваш id: …». Этот номер сохранить (перезапуск не нужен):
   ```
   python -c "open('.local/telegram_users.txt','a',encoding='utf-8').write('ВАШ_ID\n')"
   ```
   Так же добавляются коллеги — по одному id в строке. Остальным бот не отвечает.

   **Открыть бота всем** — строка `*` в `.local/telegram_users.txt`: отвечает любому. Гостю
   (кого нет в списке по id) — 20 вопросов модели в час, поиск и статьи — без
   ограничения; владельцам из списка — без ограничения. Сколько — `KBRAG_TG_GUEST_LIMIT`
   в `.local/settings.env` (0 — без ограничения); `python kbrag.py tg --check`
   предупреждает, что бот открыт всем, и пишет лимит. Вопросы модель пишет по одному:
   кто спросил, пока она занята, видит своё место в очереди. Закрыть — удалить строку
   `*`, перезапуск не нужен.

   Бот запускается в одном окне: вторая копия на этом компьютере сама не стартует
   (две копии забирают одни и те же сообщения и отвечают по нескольку раз).

Запуск:

```
python kbrag.py web --tg
python kbrag.py tg
```

Первая — страница в браузере и бот сразу, в одном окне (модель векторов одна на
двоих, видеопамяти меньше). Вторая — только бот. Просто `python kbrag.py web` (без
`--tg`) бота **не** запускает. Бот работает, пока открыто это окно; входящие
сообщения видны в нём.

Бот молчит — проверить по шагам (база и модели для этого не нужны):

```
python kbrag.py tg --check
```

Скажет, принят ли токен и как называется ваш бот (писать нужно именно ему), кому
бот отвечает, кто уже писал боту и с каким id, не запущен ли бот в другом окне.

В боте всё — кнопками. Внизу экрана постоянное меню: **Поиск**, **Статьи**,
**Датасеты**, **Новый разговор**, **Помощь**. Любой другой текст —
вопрос чат-боту.

- **Под ответом** — номера фрагментов [1], [2]… (нажал — фрагмент целиком, со
  ссылкой на статью у издателя и кнопкой «Вся статья»), «Как искал» (части
  вопроса, запросы, что модель отобрала и что искала ещё), «Новый разговор».
  Пока бот пишет — «Остановить».
- **Поиск** — бот спросит, что искать; выдача листается кнопками «‹ Назад» /
  «Дальше ›», номер открывает фрагмент, «Спросить бота об этом» задаёт запрос
  чат-боту.
- **Статьи** — весь список с листанием; у статьи — авторы, журнал, ссылка и все
  её фрагменты по порядку.
- **Датасеты** — сущности, у которых больше всего фактов, кнопками; у каждой —
  факты о ней, «Таблица для Excel» (файл CSV) и «Спросить бота» (что известно).
  Любую другую — командой `/dataset название`.

Команды тоже работают: `/kb` (с какой базой дерева работать — кнопками; выбор
запоминается у каждого и переживает перезапуск бота), `/search запрос`, `/articles`,
`/dataset название`,
`/f 2`, `/new`, `/stats` (что в базе и готова ли модель). Подробно или кратко —
пишется в самом вопросе.

Токен и список id — в `.local/telegram_token.txt` и `.local/telegram_users.txt`, в репозиторий они
не попадают.

### Граф знаний

```
python kbrag.py graph --limit 30
python kbrag.py graph
```

**Qwen3** читает фрагменты статей по одному и выписывает факты: «от — связь —
к» и дословную цитату. Например: «метод Монте-Карло — применяется для — оценки
погрешности».
Сущности — как их назвала статья (место, метод, процесс — неважно), связь —
словами статьи. Первая команда — проба на 30 фрагментах, вторая — все новые.
Около 4–5 секунд на фрагмент; прервать можно Ctrl+C, та же команда продолжит с
того же места. Нужна модель (`graph` поднимает её сам).

Каждый факт **проверяет код**: цитата должна найтись в статье дословно, а в
цитате — оба конца факта. Не прошло проверку — в граф не попадает. Что
получилось и почему код отбрасывал остальное:

```
python kbrag.py graph --new
```

Правила для модели — `graph-rules.txt` в папке базы (`config\kbs\<база>`, а нет
своего — общий `config\kbs\graph-rules.txt`), правятся Блокнотом. После правки —
`python kbrag.py graph --redo` (всё заново).

### Словарь синонимов

Одно и то же статьи пишут по-разному: «Monte Carlo method», «метод МК». Словарь
базы `config\kbs\<база>\synonyms.yaml` сводит такие написания к одному имени:

```
имена:
  метод Монте-Карло: [Monte Carlo method, метод МК, MC simulation]
```

Падеж и число не важны — «метода Монте-Карло» узнаётся само. Чего в словаре
нет, в граф идёт как написала модель. Правка действует сразу, модель заново
проходить не нужно.

Пополнять словарь помогает модель, решаете вы:

```
python kbrag.py synonyms
```

Модель находит похожие имена и решает, одно ли это. Предложения — в файле
`.local\kbs\<база>\synonyms-предложения.yaml`: откройте Блокнотом, нужные строки
перенесите в `synonyms.yaml` базы, ошибочные — просто не переносите.

### Датасеты

```
python kbrag.py dataset
python kbrag.py dataset "метод Монте-Карло"
```

Первая — у чего больше всего фактов. Вторая — все факты о методе Монте-Карло
(вместе с тем, что в него входит) и файл `.local\kbs\<база>\datasets\датасет-метод Монте-Карло.csv`
для Excel. Датасет есть у любой сущности — у места, метода, процесса. На графе в
браузере — щелчок по узлу. Заранее датасеты не создаются и нигде не хранятся:
каждый собирается из фактов, когда его открывают, поэтому после нового `graph`
новые датасеты появляются сами.

### Оценка: насколько хорошо ищет и отвечает

```
python kbrag.py eval
python kbrag.py eval --only-search
```

Вопросы — у каждой базы свои: `eval --kb physics` берёт вопросы самой базы и всех
баз под ней (`config\kbs\physics\optics\eval-questions.yaml` и т. д.), и каждый
вопрос задаётся в своей базе. Как их написать — образец в
`config\kbs\geology\ore\anabar\eval-questions.yaml` (около тридцати вопросов). Отчёт
в `.local\logs\eval-<дата>.md`: что нашлось, по базе ли ответ, не отписка ли, у скольких
утверждений есть ссылка на статью. Каждый прогон сравнивается с прошлым прогоном
той же базы; вопросы нескольких баз — ещё и таблицей «По базам».
Без модели — второй вариант, только поиск.

Где вопросам оценки не хватает статей, отчёт пишет в разделе «Где базе не хватает
статей» — их добавляет `import`.

## 5. Обычный порядок работы

```
python kbrag.py start
python kbrag.py kb create physics.optics --title "Оптика"
python kbrag.py import "D:\Статьи" --kb physics.optics
python kbrag.py graph --kb physics.optics
python kbrag.py eval --kb physics.optics
python kbrag.py web
```

Создать базу → импортировать → граф → оценить → искать и спрашивать.

### После обновления кода до новой версии — один раз

```
python kbrag.py init
python kbrag.py graph --redo
python kbrag.py synonyms
```

`init` доводит таблицы до новой схемы (а с `--kb <ветка>` кладёт в неё статьи, у
которых ветки ещё нет). `graph --redo` — граф по-новому: Qwen3
заново проходит все фрагменты и выписывает факты (4–5 секунд на фрагмент, можно
прерывать Ctrl+C и продолжать той же командой). `synonyms` — предложения в
словарь синонимов: просмотреть и перенести нужное в `synonyms.yaml` базы.

## 6. Прежняя ночная добыча

Раньше программа сама искала и скачивала статьи из интернета, в том числе каждую
ночь по расписанию. Теперь статьи — только свои (`import`). Если ночной прогон был
включён, уберите его из планировщика Windows один раз:

```
python kbrag.py unschedule
```

Добытые раньше статьи остаются в базе. PDF у них нет — только ссылка на статью;
чтобы их можно было переразобрать (`reparse`), импортируйте их файлы: `import`
узнает тот же файл и запомнит путь к нему.

## 7. Если что-то не работает

| Что видите | Что делать |
|---|---|
| `python` не является внутренней или внешней командой | Python не поставлен или без галочки «Add to PATH» — переустановить с галочкой |
| Не найдено окружение .venv | вы не в папке проекта, или раздел 3 не сделан |
| Docker не найден / не отвечает | запустить Docker Desktop, дождаться, пока кит перестанет мигать |
| База недоступна | `python kbrag.py start`, потом `python kbrag.py status` |
| Контейнер в статусе Restarting | `docker compose logs db` — там причина |
| Чат-бот: «Модель не отвечает» | `python kbrag.py start` и подождать 1–2 минуты; `python kbrag.py status` — отвечает ли |
| Модель не поднимается | `docker logs kbrag-llm` — там причина. «out of memory» — видеокарту занял другой процесс (`nvidia-smi`) |
| Телеграм-бот молчит | запущен ли `python kbrag.py web --tg` (именно с `--tg`) и открыто ли окно; дальше — `python kbrag.py tg --check` |
| Чат-бот отвечает «в базе знаний об этом нет» | в базе правда нет статей по теме — добавить: `python kbrag.py import "папка с PDF" --kb <база>` |
| В отчёте `import` — «скан» | в PDF нет текстового слоя (страницы — картинки): распознать — `import … --ocr` (`docs\КОМАНДЫ.md`, «Сканы») |
| В отчёте `import` — «не разобрана» | ни одна попытка разбора не прошла проверку; причина — в журнале `.local\logs` |
| На графе лишняя сущность или связь | `python kbrag.py graph --new` — что нашла модель; поправить `graph-rules.txt` базы и `graph --redo` |
| Одно и то же на графе двумя узлами | дописать синоним в `synonyms.yaml` базы (или `python kbrag.py synonyms`) |
| «Словарь синонимов: …» при запуске | ошибка в `synonyms.yaml` базы (путь — в сообщении) — синонимы в [квадратных скобках], через запятую; сохранять в UTF-8 |

**Никогда** не набирайте `docker compose down -v`: это удаляет базу целиком.

## 8. Что где лежит

```
kbrag.py            ← вход для всех команд
ЗАПУСК.md           ← этот файл
README.md           ← коротко о проекте
config\             ← всё, что правится руками
   kbs\                 дерево баз знаний — папка на каждую базу (раздел «Дерево баз»)
      kb.yaml              корень: база по умолчанию, слова темы и промпты для любой базы
      graph-rules.txt      правила графа для базы без своих
      <ветка>\            база: kb.yaml, synonyms.yaml, graph-rules.txt, eval-questions.yaml
      geology\             образец — база о рудной геологии, с которой начинался проект
docs\               ← КОМАНДЫ.md — все ключи; УСТРОЙСТВО.md — как устроено
kbrag\              ← сам код
   library\            свои статьи: import, reparse, метаданные
   parse\              разбор PDF
   index\              база, векторы, поиск
   graph\              граф знаний: факты, синонимы, датасеты
   chat\               чат-бот
   web\                страница в браузере
tests\              ← проверки кода и эталонные PDF (python kbrag.py test)
.local\             ← только для этой машины (в git не идёт): разобранные
                      статьи, логи, ключи и токены
docker-compose.yml  ← описание базы
requirements.txt    ← список библиотек
requirements-dev.txt ← только для проверок кода, без docling и torch (CI)
```
