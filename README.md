# KBRAG — базы знаний по научным статьям

Локальная база знаний по вашим статьям на любую тему — баз может быть
несколько, деревом. Разбирает PDF с диска (`python kbrag.py import`) на фрагменты с номерами
страниц, формулами и рисунками и отвечает:

- **Поиск** — фрагменты статей по смыслу и по точным словам, русский запрос
  находит и английские статьи;
- **Статьи** — всё, что разобрано, с разбором по фрагментам;
- **Чат-бот** — ответ Qwen3 по статьям базы, с номером фрагмента после каждого
  утверждения. Ищет вместе с моделью: Qwen3 разбирает сложный вопрос, читает
  найденное, берёт подходящее и ищет недостающее. Если в базе такой информации нет, бот так и пишет
  и отвечает из общих знаний модели — с пометкой, что это не из базы. На
  своей вкладке — граф знаний, как в Obsidian, с поиском узла.

Граф знаний — факты из статей: «метод Монте-Карло — применяется для — оценки
погрешности», с дословной цитатой. Выписывает их Qwen3 по правилам базы
(`config/kbs/<база>/graph-rules.txt`, а нет своих — общие `config/kbs/graph-rules.txt`),
код проверяет каждый: цитата должна быть в статье, а в цитате — оба конца.
Разные написания одного и того же сводит словарь синонимов
базы (`config/kbs/<база>/synonyms.yaml`); пополнять его помогает модель, решает человек.

У любой сущности графа есть датасет — все факты о ней с цитатами и статьями:
`python kbrag.py dataset "метод Монте-Карло"`. Вопросы о связях («с чем
связан …», «что известно о …») чат-бот ведёт по графу,
остальные — поиском по фрагментам.

Качество поиска и ответов проверяется набором вопросов: `python kbrag.py eval`.

То же — в Телеграме: `python kbrag.py web --tg` (страница и бот сразу).

Для Claude Code — MCP-сервер (`python kbrag.py mcp` поверх `serve`: поиск, фрагменты,
статьи, факты, формулы, рисунки) и `--json` у `search`, `facts`, `ask`.

Всё работает на одной машине: PostgreSQL с pgvector в Docker, BGE-M3 для
векторов, Docling для разбора PDF, Qwen3 в vLLM (Docker, протокол OpenAI).

```
python kbrag.py web
```

| все команды и ключи | `docs/КОМАНДЫ.md` |
| как устроено внутри | `docs/УСТРОЙСТВО.md` |

Коротко:

```
python kbrag.py kb create physics.optics --title "Оптика"
python kbrag.py import "D:/Статьи/Оптика" --kb physics.optics
python kbrag.py web --tg
```

## Что где лежит

```
kbrag.py       вход для всех команд: python kbrag.py help
config/kbs/     дерево баз знаний, правится Блокнотом: у каждой базы своя папка — тема, синонимы, правила
                графа, вопросы оценки; чего у базы нет, берётся у ветки выше
kbrag/         код: library (import, reparse) · parse · index · graph · chat · web · evaluation
                общее: kb (дерево баз) · llm (сервер модели, vLLM) · text · lang · common
docs/           справочник и устройство
tests/          проверки кода и эталонные PDF: python kbrag.py test (без базы и модели)
.local/         только для этой машины: статьи, логи, ключи (в git не идёт)
```

Сами PDF не копируются: остаются путь к файлу, его отпечаток, разобранный текст
и рисунки файлами.
